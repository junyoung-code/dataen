## 격자 입력의 실제 구현

- 수집 W410: 8기상변수 × 725점, 1,976일 완료·시간별 표 결측 0이라는 팀원 기록. 입력 전부를 모델에 넣은 것은 아니다.
- 채택 F153/F155: 일사량과 전체·하층·중층·상층 운량, 총 5변수에서 각각 PCA 5개씩 추출해 25열을 추가한다. PCA는 여러 격자의 변화 패턴을 적은 수의 숫자로 압축하는 방법이다.
- 모든 발전소에 같은 25열을 붙이고 기존 위경도 입력과 함께 학습한다. 발전소마다 가까운 격자를 골라 붙이는 구현이 아니다.
- `F153_grid_pca.py`와 `gfs_grid.py`에서 평균·표준편차·PCA를 각 검증 시작 전 낮 시각으로만 맞추는 것을 확인했다. F155는 같은 함수를 재사용하고 청천비 목표를 유지한다.
- 수집기는 대상일 전날 00 UTC 실행본, 없거나 깨지면 전전날 실행본을 사용한다. 공개 시각 검사는 실행+5시간 가정이며 모든 과거 파일의 실제 공개 이력을 이번에 독립 감사한 것은 아니다.

팀원 세 해 seen 과거 짝 비교에서 F153 추가는 W 1.03%/1.12%/0.94%, 그 위 F155 추가는 0.79%/0.83%/0.44% 감소했다. 각각 이전 단계 대비 수치이므로 단순 합산하지 않는다. 공식 서버는 두 변경을 합친 S927만 제출해 각각의 서버 기여는 분리되지 않는다.

## 다른 방법과 해석의 한계

신경망 혼합·20시드 평균·권역별 GFS 입력도 사용했다. 검증 채점도 실제 제출에 맞춰 학습 이력이 있는 발전소(seen)를 중심으로 바꿨다. 채점 대상 변경 자체가 예측을 개선하는 것은 아니며, 이전 all 점수와 직접 비교해서는 안 된다. F1~F3는 반복 확인한 과거 평가다. 보정 짝에는 F2←F3처럼 미래 해로 과거 해를 보정하는 경로가 남아 있어 우리 과거→미래 평가와 같은 재현이라고 부르지 않는다.

격자 입력을 신경망·팀 직접 모델에 추가하거나, 격자 기온·습도·강수를 더 넣거나, GFS 여러 발행 회차를 평균하거나, CatBoost·유사일 방법·팀 재배정을 시도한 후보는 채택되지 않았다. 데이터나 모델 수를 늘리기만 하면 좋아진다는 증거는 아니다.

CAMS는 GFS와 별도 예보 자료다. 이번 공식 최고 S927에는 CAMS가 없으며 11/8 후속 후보 S929에 추가 중이다. 팀원 규정 해석은 11/4 통합 공지(11/5 수정)를 근거로 하나, 이번 확인에서 공식 공지 원문을 새로 검증하지 않았다.

### 후속 질문 — 기상청 승인과 역할 분담

11/8 재확인: 우리 `access_status.json`에는 기상청 API 허브의 `nwp_vars_down.php`(과거 UM/KIM)·`nwp_nc_vars_down.php`(KIM) 활용신청 2건 승인, 사용기간 2026-11-06~2028-11-06, 실제 인증 API 요청 미시험·기상 파일 0으로 기록돼 있다. 로컬 `.env`의 KMA 키 존재도 값 출력 없이 확인했다. API 허브 공식 첫 화면도 수치모델(UM/KIM)과 예특보(단기예보 등)를 구분한다([11/8 조회](https://apihub.kma.go.kr/main.do)). 팀원은 기상청 단기예보를 키 발급·호출 제한·서버 종료 때문에 보류했다고 기록했다. 우리가 승인받은 수치모델 API와 같은 서비스라고 단정하지 않는다.

역할 분담 제안은 CAMS는 이미 수집·시험 중인 팀원이 계속하고, 기상청은 승인 자원을 가진 우리 쪽에서 소량 인증 시험과 과거 예보 가용 기간·변수·발표시각 확인을 맡는 것이다. 이는 제안이며 실제 분담 합의나 새 수집 지시는 아니다. 이번 확인에서 API 호출·수집 재개·팀원 연락은 하지 않았다.

## 11/8 팀원 산출물 공유 실물 조사

사용자가 연 Chrome `https://github.com/aiswody/oibc2026`를 직접 확인했고, API에서도 원본 저장소 `fork=false`를 확인했다. 이전 peer_source도 이 원본의 고정 커밋 사본이며 사용자 fork만 보고 있던 것은 아니다. 현재 main `5038ff5` 및 나머지 4개 브랜치의 전체 트리(잘림 없음)를 조사했다. 실제 학습 가중치/기상 parquet/OOF parquet/압축 묶음은 발견되지 않았고, GitHub Releases 0 · Actions artifacts 0 · Issues 0이었다. `params_S927/S928.json`은 재현 설정이며 학습된 모델 가중치가 아니다.

원본 문서는 실제 산출물을 GitHub 밖 `oibc_work`에 보관한다고 명시한다. `external/gfs/gfs_hourly_v1.parquet`, `gfs_hourly_v2.parquet`, `gfs_grid_v1.parquet`, `external/cams/cams_hourly_v1.parquet`와 `outputs/*_oof_F2/F3.parquet`를 우선 공유받으면 중복 기상 수집 및 변경하지 않는 모델 재학습을 줄일 수 있다. `*_final_eval_sites.parquet`/`submissions/.../forecast.csv`는 최종 예측 결과로 검증용과 구분한다. GitHub에 실제 가중치가 없으므로 그 가중치의 검증용/최종용 판별은 아직 불가능하다. 팀원 개인 폴더에 없다는 뜻은 아니다.

정확한 공유 링크/파일명을 요청했고 사용자가 “일단 팀원이랑 이야기 해볼게”라고 답해 추가 탐색을 중단했다. 사용자에게 링크를 받기 전 새 전송/다운로드/학습이나 기존 프로세스 변경은 하지 않는다. 조사 근거는 로컬 `outputs/runs/peer_artifact_audit_20261108/summary.json`·브랜치별 tree 및 원본 문서 사본에 보존했다. 출처: 원본 README 데이터 정책, docs/05_compute.md, reproduce/run_all.py, PROGRESS.md.
