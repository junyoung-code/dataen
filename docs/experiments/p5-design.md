# P5 팀 배정 탐색과 설정 고정 후 역사적 확인

2026-11-03 KST, 결과 확인 전 확정. 사용자 요청에 따라 팀 배정을 탐색한 후 별도 확인 구간에서도 기존 배정과 비교한다. 공식 제출은 하지 않는다.

## 고정 예측과 탐색

- P4 선택 모델: 거리 포함 26특징·200트리·0.03·25:75·regression_l1·용량 가중. tune 저장 예측을 그대로 사용한다. 예측값·모델·관측 표본은 바꾸지 않는다.
- 초기 배정은 제공 current_group의 A→G1/B→G2. 253개 발전소를 한 번씩만 배정하고 각 팀 설비용량 20,000kW 이상을 유지한다. 위치 추정·원본 수정 없음.
- tune은 P0의 2025-01-01 01:00~2025-03-01 01:00 KST(끝 미포함), 모든 발전소 실측이 있는 1,416시간이다. 원본 실측과 예측을 먼저 팀별 합산한 뒤 SMP×k 가중 MAE를 계산한다.
- 시간별 잔차는 예측−실측. 두 팀 목적함수는 `sum(w*(abs(r1)+abs(r2)))/(2*sum(w))`. 전체 발전소 잔차 합은 배정과 무관하다. `sum(w*abs(r1+r2))/(2*sum(w))`는 삼각부등식에서 얻는 하한이며 도달 가능성이나 전역 최적성을 보장하지 않는다.
- 각 단계에서 용량 제약을 만족하는 단일 이동 및 G1/G2 사이 두 발전소 교환을 모두 비교한다. 최고 개선 한 건만 적용한다. 1e-9kWh 이하 개선은 무시한다.
- 최대 50회 또는 더 나은 유효 이동/교환이 없을 때 종료. 초기 배정 한 개에서 시작하며 무작위 재시작·추가 튜닝은 하지 않는다. 발전소 ID 정렬, 단일 이동 먼저, 이후 사전순 교환으로 동률을 결정한다. 국소 탐색 결과이며 전역 최적 배정이라고 부르지 않는다.
- 선택된 배정은 전체 평가 기간에 고정한다. 시간마다 다르게 배정하지 않는다.

## 배정 고정과 확인

1. tune만으로 배정을 선택하고 `optimized_assignment.csv`, `selection.json`에 모델 설정·SHA-256·탐색 경로를 저장한다.
2. 그 후에만 계절 진단 및 확인을 수행한다. 추가 교환·모델 선택은 없다.
3. 계절 진단은 P4의 과거 모델 저장 예측을 재사용하고 두 배정 모두 같은 253개 공통 178시간(12월 일부)에만 비교한다. 배정에 따라 달라지는 완전 관측 시간을 사용하지 않는다.
4. 확인은 P0 계획대로 학습 [2023-06-01 01:00, 2025-02-28 01:00), 24시간 제외 후 평가 [2025-03-01 01:00, 2025-06-01 01:00), KST. P4 설정을 고정한 두 모델만 다시 학습한다. 학습 기간 확장은 확인 프로토콜에 따른 것이며 결과를 보고 선택하지 않는다.
5. 확인의 같은 발전소 예측에 참조 배정과 고정 배정을 각각 적용한다. 공통 2,208시간(100%)에서 비교하므로 차이는 배정 효과다. 전체 P0~P4 모델 개선 효과를 평가하는 비교가 아니다.
6. 확인 점수가 나빠도 탐색을 다시 하지 않고 결과를 그대로 기록한다. 공식 제출 채택 여부는 별도 판단한다.

확인 기간은 P1~P4의 설정 선택에는 사용하지 않았지만 이전 1년 보고서에서 본 역사적 기간이다. 따라서 완전 미사용 독립 테스트라고 부르지 않는다. 이번 이후 이 기간은 P5 결과까지 확인한 기간임을 기록한다. 탐색을 계속하면 같은 확인 구간을 새로운 독립 평가처럼 재사용하지 않는다.

## 기록과 검증

- 실행 코드·명령·기기·버전, 원본 해시, 고정 마스크, 변경 발전소 수, 팀별 용량·개수, 탐색 횟수·중단 이유·하한·시간·메모리.
- tune/계절/확인 각각의 주 지표, 팀별·월별 결과와 악화 구간. 모델 예측은 같은데 팀 구성만 바뀌는지 확인한다.
- 단위 테스트는 오류 상쇄, 실제 가능한 교환의 점수, 작은 예제의 완전 열거 대조, 용량·누락·중복 제약, 불필요한 변경 방지를 검사한다.
- 별도 계산으로 배정 제약과 모든 점수·고정 해시·확인 모델의 날짜/트리/특징/재로딩을 검증한다. 배정 파일·행 단위 예측·모델은 outputs에만 보관하고 Git에는 집계·코드·문서만 남긴다.
