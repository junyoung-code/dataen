## 최신 다음 시작점 — 모델 고정 후 데이터 확보

새 구조·혼합비·배정 탐색보다 아래 데이터 확보를 우선한다. 이후 데이터 추가 비교에서는 모델 계열/튜닝값/혼합비/배정을 고정하고 동일한 시간순 조건으로 재학습한다. 기존 학습 가중치를 새 입력에 그대로 적용한다는 뜻은 아니다. 기준선 재현 때 미래 fold 보정을 그대로 가져오지 않으며, 그에 따른 점수 차이와 데이터 추가 효과를 분리한다. 후속 요청에 따라 실제 수집을 시작했다. `CONTEXT.md`의 실제 기상 자료 수집 항목과 실행 폴더의 최신 manifest를 우선한다.

### 필요한 이유에 대한 연구 근거

- 일사와 다른 기상 예보가 태양광 예측의 핵심 입력이며 앙상블의 불확실성을 출력 예측까지 전달하는 접근은 [2023년 연구](https://doi.org/10.1016/j.rser.2023.113171)에서 다룬다. 이번에는 발전량 모델을 바꾸지 않고 여러 예보의 값/차이/산포를 기존 모델의 입력으로 시험한다는 가설이다. 논문 전문 열기는403이었으며 공개 초록 범위로만 근거를 사용했다.
- 맑은 하늘에서도 에어로졸은 직접/전일사량에 영향을 준다. [Breitkreuz 등,2009](https://elib.dlr.de/58984/)는 화학수송모델의 에어로졸 예보와 기상 정보를 결합해 일사를 예측한다. CAMS 후보의 물리적 근거이지 우리 W 개선의 증거는 아니다. 기관 저장소의 검색 공개 초록을 확인했으며 전문을 읽었다고 보고하지 않는다.
- [Baguan-solar,2026 사전논문](https://arxiv.org/abs/2603.14845)은 동아시아 하루전 일사 예측에서 광역 기상 예보와 정지궤도 위성 정보를 결합한다. 위성 후보의 근거로만 사용하며 해당 신경망 구조를 이번 고정 모델에 도입하거나 논문의 개선율을 우리 대회 개선율로 옮기지 않는다.

## P0 — 먼저 평가 방식을 확정

목적: 실험마다 같은 조건으로 비교하고, 이미 본 데이터에 맞춘 결과를 새 미래 성능으로 오해하지 않도록 한다.

- 제공 `data/README.md`와 최신 공식 문제정의서에서 정산식, 제출 제약, 사용 가능한 정보의 시점을 대조한다. 공식 페이지를 읽을 수 없으면 미확인 항목을 명시한다. 외부 데이터·사전학습 모델 허용 여부를 추정하지 않는다.
- 시간순으로 학습 → 튜닝 → 최종 확인 구간을 정하고 경계·예측 발행 시점·제외 구간을 기록한다. 확정 날짜와 선택 규칙은 [평가 프로토콜](../../../docs/experiments/evaluation/validation-protocol.md)을 따른다.
- 기존 검증 연도는 이미 전체·월별 결과를 확인했다. 그 일부를 새로 잘라서 완전히 미사용인 독립 테스트라고 부르지 않는다. 새로운 미사용 구간 확보 가능성을 확인하고, 확보하지 못하면 그 한계를 명시한 시간순 반복 검증으로 비교한다.
- 주 지표는 제공 정산식에 대응하는 **팀 합산 발전량의 SMP·시간대 가중 절대오차**로 검토한다. 보조 지표는 팀 MAE/RMSE, 낮 시간 발전소 정규화 MAE, 월별·팀별·기존/신규 발전소 성능으로 둔다.
- 결측 실측을 0으로 채우지 않는다. 비교 후보는 동일한 관측 표본으로 평가하고, 평가 포함 비율을 함께 보고한다. 팀 배정 후보별로 평가 시간이 달라지지 않도록 공통 비교 시각을 먼저 고정한다.
- 조기 종료에 쓰는 기간은 튜닝용이다. 최종 확인 구간의 결과로 트리 수·특징·가중치·팀 배정을 반복 선택하지 않는다.

완료 조건: 날짜, 정보 이용 가능 시점, 지표 수식, 고정 평가 표본, 선택 규칙을 `docs/experiments/validation-protocol.md`에 기록하고 필요한 시간 경계·결측 검사를 통과한다. 완료: 해당 문서 작성, 원본 3개 해시 대조, 전체 관측 범위 감사 및 테스트 11개 통과.

## P1 — 트리 수와 학습률

- 가설: 실행 확인용 50개 트리보다 학습량을 늘리면 검증 오차가 줄어들 수 있다. 개선은 측정으로 판단한다.
- 1차 후보: `n_estimators = 50, 200, 600` × `learning_rate = 0.03, 0.06`의 6개 설정.
- 특징, 데이터 구간, 팀 배정, 그 외 파라미터와 난수 시드는 고정한다. 각 설정에서 10시·17시 모델을 각각 학습하고 먼저 50:50 평균으로 비교한다.
- 기존 50트리·학습률 0.06을 **새 평가 방식에서도** 기준선으로 포함한다. 기존 보고서와 평가 기간이 다르면 점수 자체를 직접 비교하지 않는다.
- 현 `evaluate_temporal.py`는 날짜·파라미터·50트리 검사가 고정돼 있다. 실험 전에 별도 설정 가능한 실행기를 마련하고 기존 검증 재현 경로를 보존한다.
- 1차는 고정 트리 수 비교로 시작한다. 필요할 때 별도 실험으로 조기 종료를 추가하며 두 조건을 혼동하지 않는다.

완료 조건: 6개 설정의 주·보조 지표, 월별 결과, 학습 시간·최대 메모리·선택 근거를 기록한다. 큰 트리 수를 자동으로 승자로 정하지 않는다.

P1 완료: 24개 모델 학습, 단위 테스트 14개 및 저장 예측 독립 재계산 통과. [상세 보고서](../../../docs/experiments/p0-p5/2026-11-03-p1-grid.md). 기존 시험 학습 기본값은 유지하며 최종 제출 모델은 미확정이다.

## P2 — 두 예보 모델의 혼합

- 가설: 현재 팀 MAE에서 17시 모델이 소폭 우수하므로 50:50보다 17시 비중을 높이는 것이 유리할 수 있다.
- 후보: `예측 = (1-w) × 10시 예측 + w × 17시 예측`, `w = 0.5, 0.75, 1.0`.
- P1 후보의 저장된 튜닝 구간 예측을 재사용할 수 있다. 가중치는 튜닝 구간에서만 선택하고 최종 확인 구간에는 고정 적용한다.
- 작은 평균 차이는 월별·팀별 일관성도 확인한다. 17시 단독이 항상 최선이라고 단정하지 않는다.

완료 조건: 동일 표본에서 3개 혼합 비율을 비교하고 선택한 비율과 근거를 기록한다.

P2 완료: 25:75 혼합 선택, tune 주 지표 598.463 → 595.754kWh(0.45% 감소). 2월·G1은 소폭 악화해 월별·팀별 일관성은 없다. [결과·검증·한계](../../../docs/experiments/p0-p5/2026-11-03-p2-blend.md).

## P3 — 특징 개선

기준선은 P1·P2의 200트리·0.03·10시 25%/17시 75%다. 한 번에 한 묶음씩 추가해 어떤 변경이 효과가 있었는지 확인한다.

1. **예보 갱신 차이:** 같은 대상 시각의 17시−10시 운량·기온·강수 등의 차이. 두 라운드는 제공 안내상 전일 17시에 이용 가능하지만 실제 조인 키와 누락 처리를 검증한다.
2. **제공사 간 차이:** A/B 예보 차이와 결측 여부. 단위를 통일한 변수끼리 비교한다. 예를 들어 풍속은 A가 m/s, B가 km/h다.
3. **발전소·관측지점 특성:** 발전소/관측지점 ID, 제공 거리, 과거 자료만으로 만든 발전소별 편향 후보. 분할별 학습 이력 없는 발전소(현재 tune 0개, 계절 진단 29개)에 대한 대체 처리와 성능을 별도로 확인한다.

예측 대상 시각의 실제 발전량·실측 기상을 입력에 넣지 않는다. 과거 발전량이나 예보 오차 통계를 추가할 때도 예측 발행 시점 이전의 수신 가능 자료만 사용하고 시간순으로 계산한다.

완료 조건: 추가 특징별 효과와 월별·신규 발전소 영향, 누출 검사 결과를 기록한다. 효과 없는 묶음은 채택하지 않는다.

P3 1차 완료: [사전 설계](../../../docs/experiments/p0-p5/p3-design.md)의 세 묶음을 각각 비교해 거리 2개(wa_dist/wb_dist)를 추가한 26특징 채택. tune 595.754 → 588.630kWh, 계절 공통 441.441 → 427.753kWh. 일부 월 악화와 ID·과거 편향·묶음 조합 미실행은 [결과 보고서](../../../docs/experiments/p0-p5/2026-11-03-p3-features.md) 참조.

## P4 — 정산 목적에 맞는 학습

- 거리 포함 26특징·200트리·학습률 0.03·25:75 혼합을 고정하고 기존 목적함수와 `regression_l1`을 비교한다.
- 이후 별도 후보로 SMP·시간대 가중치 반영을 검토한다. 정규화 발전량을 학습하므로 설비용량에 따른 kWh 환산도 고려한다.
- 발전소별 가중 손실을 줄이는 것이 팀 합산 절대오차를 직접 최소화하는 것과 같지는 않다. 채택 여부는 팀 합산 예측의 주 지표로 결정한다.
- 시간대·가격을 강조한 모델이 다른 월·팀에서 크게 악화되지 않는지도 보고한다.

완료 조건: 목적함수 변경과 가중치 변경의 효과를 구분해 기록한다.

P4 완료: [사전 설계](../../../docs/experiments/p0-p5/p4-design.md)의 5후보 중 L1+용량 가중 선택. tune 588.630 → 578.439kWh(1.73% 감소), 계절 공통 427.753 → 439.781kWh(2.81% 악화). [결과·검증·한계](../../../docs/experiments/p0-p5/2026-11-03-p4-objectives.md). 시간대·가격 가중은 채택하지 않았다.

## P5 — 팀 배정 최적화

- 현재 참조 A/B 배정을 기준선으로 유지하고, P4 L1+용량 후보의 시간순 예측 오차를 사용한다. 입력은 맥 미니 `outputs/p4_20261103_132834/tune/l1_capacity/site_predictions.parquet`다. 학습 데이터에 직접 맞춘 잔차만으로 배정을 선택하지 않는다.
- 가설: 서로 반대 방향으로 틀리는 발전소를 같은 팀에 배치하면 팀 합산 오차가 줄어들 수 있다.
- 두 팀 모두 설비용량 20,000kW 이상, 253개 발전소 누락·중복 없음, 평가 기간에 고정된 한 가지 배정이라는 조건을 검사한다.
- 처음에는 제약을 만족하는 발전소 교환 탐색 등 작은 탐색으로 시작한다. 튜닝 구간에서 선택한 배정을 이후 확인 구간에 고정 적용한다.
- 후보 배정에 따라 완전 관측 시간이 바뀌는 효과를 개선으로 착각하지 않는다. P0의 공통 평가 시각·포함 범위로 비교한다.

완료 조건: 기존 배정 대비 가중 오차 변화, 용량 제약, 월별 안정성과 평가 범위를 기록한다.

P5 완료: [사전 설계](../../../docs/experiments/p0-p5/p5-design.md)의 33회 교환/이동으로 65개 소속 변경. tune 1.79% 개선, 계절 공통 0.49% 개선, 배정 고정 후 3~5월 확인은 0.35% 악화. 현재 기준은 기존 참조 배정 유지. [결과·검증·한계](../../../docs/experiments/p0-p5/2026-11-03-p5-assignment.md). **3~5월은 실제 확인한 기간이므로 이후 추가 실험에서 새로운 독립 테스트로 부르지 않는다.**

## 다음 시작 지점

- 상대 연간 W 비교도 완료했다. [W 보고서](../../../docs/experiments/evaluation/2026-11-03-peer-w.md)와 유효 `_rescore` 결과를 읽고4모델을 재학습하지 않는다. 평가 기간·W·부분 관측 마스크는 상대와 같고 우리 학습 끝만7시간 앞선다. 기존 p0-v1 가중 MAE와 직접 비교하지 않는다. 다른 후보의 연간 W는 미실행이며 후속 요청의 범위에서 정한다.

- 최신 완료: TabM·LSTM은 맥북, TFT는 맥 미니에서 학습·독립 검증을 마쳤다. [신경망 결과](../../../docs/experiments/models/2026-11-03-neural.md)를 먼저 읽는다. 현재 LightGBM 유지, TabM 추가 탐색 우선·TFT도 후보이며 이번 1차 실행을 반복하지 않는다. 새 요청에 따라 추가 튜닝·혼합 등을 정한다.
- P0~P5 1차는 완료했다. 현재 작업 기준은 P4 L1+용량 모델 후보 + 기존 참조 배정이다.
- [모델 비교 계획](../../../docs/plans/MODEL_COMPARISON_PLAN.md)의 CatBoost·XGBoost 1차 비교와 다른 기간 확인은 완료했고 현재 LightGBM을 유지한다. 신경망 세 모델도 1차 완료했으므로 TabM 추가 탐색·TFT 재확인·혼합 등을 다음 요청의 목적에 맞춰 정한다. 후보 개수·반복 횟수는 실행 시간과 결과에 맞춰 정한다.
- 최신 XGBoost 실행 코드 `1fbf67e`, 결과는 현재 맥북 `outputs/xgboost_20261103_150530/`다. 비교 당시 SSH 인증 실패로 맥북에서 세 모델을 재학습·검증했다. 이후 SSH는 복구했고 정상 연결의 무기한 재사용을 설정했다. `ssh -O check macmini`와 로컬에만 있는 코드·결과 문서의 동기화 상태부터 확인한다. 후속 행 단위 점검에서도 평가 조건은 같았지만 튜닝 기회는 달랐다.
- CatBoost 코드 `199bada`와 결과 문서는 GitHub에 미반영이다. 자동 승인 검토가 원격 main push를 거절해 맥 미니의 분리 worktree `catboost_compare_199bada/`에서 실행했다. 원본 결과는 그 폴더의 `outputs/catboost_20261103_144056/`에 있다. 기존 맥 미니 main은 0539472이며 Git 상태를 확인한 뒤 요청 범위에서 공유한다.
- 최종 학습 요청 시 규정·제출 형식과 선택 설정을 검토하고 제공 학습 구간 전체로 학습할 범위를 정한다. 전체 P0~P4 모델 개선을 독립 확인했다고 가정하지 않는다.
- 추가 실험 요청 시 이미 본 기간을 명시한 새로운 검증 설계를 먼저 정한다. P5 확인 결과를 보고 반복 교환하지 않는다.
- 실제 최종 제출은 별도 요청에 따른다.
