# B 과정: 왜 진행했고, 어떻게 비교했고, 무엇을 얻었나

2026-11-04에 시작해 2026-11-05 KST에 실행·검산·기록을 마쳤다. **이번 조건에서는 GEFS 영역 요약을 추가한 B1이 두 분할 모두 개선했다.** 사전학습 모델 두 후보는 이번 문맥 크기와 설정에서 P4보다 악화해 교체 후보로 선택하지 않는다.

| 모델 | F2 W | P4 대비 | F3 W | P4 대비 |
|---|---:|---:|---:|---:|
| 기존 P4 | 1,121,486,496.850 | 기준 | 2,063,719,840.542 | 기준 |
| P4 + GEFS 영역 요약 | 1,039,175,004.310 | -7.339% | 1,998,466,851.636 | -3.162% |
| TabPFN v2 · 8,192문맥 | 1,168,621,543.477 | +4.203% | 2,084,775,339.748 | +1.020% |
| TabICLv2 · 8,192문맥 | 1,182,359,161.396 | +5.428% | 2,166,110,322.429 | +4.961% |

W는 낮을수록 좋다. 같은 F2/F3 기간·원본 라벨·평가 키/부분 관측 마스크·기존 팀 배정·25:75·정산 가중치를 유지했다. 기존 P4 네 모델은 재학습하지 않고 검증된 `_rescore` 예측을 재사용했다.

## 왜 B 과정을 진행했나

기존 P4는 제공 기상 예보와 시간·위치·설비용량 등 26개 입력을 쓰는 LightGBM이었다. 앞선 실험에서 트리 수, 두 예보의 혼합 비율, 특징, 학습 손실을 비교한 상태였다. B 과정은 여기서 개선할 수 있는 두 방향을 실제로 확인하는 작업이었다.

| 실험 | 확인하려던 질문 | 바꾼 부분 | 이유 |
|---|---|---|---|
| B1 | 다른 기상 예보를 추가하면 기존 모델이 더 잘 예측할까? | GEFS 요약 4개 추가, 26→30개 입력 | 태양광에 직접 관련된 일사량·구름과 예보의 불확실성 정보를 보충 |
| B2 | 이미 다른 표 형태 자료의 패턴을 배운 모델이 도움이 될까? | 기존 26개 입력으로 TabPFN v2 사용 | 새로 큰 신경망을 학습하지 않고 과거 사례를 문맥으로 제공하는 방식 시험 |
| B3 | 같은 문맥 조건에서 다른 사전학습 모델은 어떨까? | 기존 26개 입력으로 TabICLv2 사용 | B2와 같은 사례·평가로 다른 후보 비교 |

예를 들어 같은 시각의 제공 예보가 비슷해도, 다른 예보 모델의 일사량·구름 판단이나 31개 예보 사이의 차이가 추가 단서가 될 수 있다는 것이 B1의 가설이다. 이번 결과는 **4개 정보를 함께 추가한 효과**이며, 어떤 한 정보가 개선을 만들었는지 따로 검증하지는 않았다.

B2/B3의 “사전학습”은 외부에서 미리 학습된 가중치를 가져온다는 뜻이다. 이번 과제에서는 가중치를 다시 학습하는 파인튜닝을 하지 않았다. 과거 입력과 정답 8,192쌍을 참고 사례로 제시하고 새로운 입력의 발전량을 추론했다.

## 어떤 순서와 기준으로 진행했나

1. **비교 기준부터 고정했다.** 기존 P4 예측, 두 평가 기간, 관측이 있는 행, 팀 배정, 10시·17시 예보의 25:75 혼합, 밤의 예측 0 처리, 점수 계산을 동일하게 유지했다. 점수가 좋아 보이는 행만 골라 평가하지 않았다.
2. **B1 자료의 의미와 사용 시점을 확인했다.** 공개 GEFS의 단위·예보 구간·라이선스를 확인하고, 한국의 고정된 넓은 영역을 요약했다. 발전소별 외부 격자 매칭은 하지 않았다. 미래 실측이나 늦게 발행된 예보를 쓰지 않도록 발행 가능 시점 가정을 명시했다.
3. **작게 시험한 뒤 전체 기간을 수집했다.** 3일 시험으로 시간 처리와 합계를 확인한 후 1,461일을 수집했다. 연결 오류 48일을 같은 스냅샷에서 다시 받아 누락 0일로 마쳤다. 기존 LightGBM 설정을 그대로 적용해 B1을 평가했다.
4. **B2/B3의 로컬 실행 조건을 먼저 정했다.** 맥북 메모리와 MPS에서 합성 입력으로 실행 가능성을 확인한 뒤 8,192문맥·앙상블 1개를 고정했다. 실제 연간 결과를 보고 조건을 다시 고르지 않았다. 공개 가중치를 내려받은 뒤 실제 대회 자료 계산은 네트워크를 차단한 로컬 환경에서 진행했다.
5. **전체 평가와 독립 검산을 했다.** B1→B2→B3 순서로 각각 두 연도의 전체 평가 자료를 예측했다. 별도 코드로 원본 정답·평가 키·월별 및 팀별 점수를 다시 계산하고, 저장한 모델 또는 문맥으로 일부 예측을 다시 만들어 일치 여부를 확인했다.

| 구분 | 과거 학습 자료 범위(KST, 끝 포함) | 평가 범위(KST, 끝 제외) | 평가 발전소×시간 행 |
|---|---|---|---:|
| F2 | 2021-06-01 01:00 ~ 2023-05-31 17:00 | 2023-06-01 01:00 ~ 2024-06-01 01:00 | 1,256,595 |
| F3 | 2022-06-01 01:00 ~ 2024-05-31 17:00 | 2024-06-01 01:00 ~ 2025-06-01 01:00 | 2,170,645 |

W는 팀 발전량 예측의 절대오차에 가격·시간대 가중치를 적용한 합계다. 예를 들어 P4 대비 −7.339%는 같은 평가 자료에서 이 오차 합계가 7.339% 줄었다는 의미다. 정확도 7.339%포인트 상승이나 대회 공식 점수 상승을 뜻하지 않는다. F2와 F3는 관측량·기간이 다르므로 절대 W끼리 비교하지 않고 각 기간의 P4 대비 변화를 본다.

## 결과를 어떻게 해석했나

**B1을 다음 성능 후보로 보존한다.** 두 평가 연도, 두 팀에서 W가 모두 줄어 추가 예보 정보의 가능성을 확인했다. 다만 특정 달에는 악화했고, 별도의 정보별 기여도 검사나 통계적 유의성 검사는 하지 않았다. 모든 계절과 새로운 미래에도 개선된다고 확정할 수 없다.

**B2/B3는 이번 설정에서 교체 후보로 선택하지 않는다.** 두 평가 연도의 전체 W가 모두 증가했다. 두 모델이 참고한 정답은 8,192개로, P4의 낮 학습 행 약 47.7만/96.3만 개보다 훨씬 적다. 문맥 크기·샘플링·앙상블을 바꾸면 결과가 달라질 가능성은 있으나 이번에 측정하지 않았다. 악화 원인을 표본 수 한 가지로 단정하거나 모델 계열의 최대 성능 순위로 일반화하지 않는다.

다음 결정에 사용할 근거는 B1의 개선과 월별 한계다. GEFS를 다른 모델에 추가하거나 A 결과와 섞는 작업, 최종 학습 및 제출은 아직 수행하지 않았다. 이미 본 F2/F3는 역사적 비교이며 새로운 독립 최종 시험이 아니다.

## 비교의 범위

- B1은 기존 26개 입력에 한국 고정 영역의 일사량·구름 앙상블 평균/산포 4개를 추가했다. 발전소별 외부 격자 매칭 없이 같은 시각의 요약을 모든 발전소에 동일하게 붙였다. 전체 1,461일·35,064시간 수집을 마쳤고 DNS 오류 48일은 같은 스냅샷에서 다시 받아 최종 누락은 0일이다.
- B2/B3는 기존 26개 입력과 동일한 과거 8,192개 낮 문맥을 사용했다. 용량에 비례해 중복 없이 선택하고 학습 구간의 중앙값으로만 결측을 처리했다. 내부 앙상블 1개·중앙값 예측·고정 사전학습 가중치를 사용했다. P4의 전체 낮 학습 행 F2 476,693개/F3 962,913개와 라벨 수가 다르며, 용량 비례 샘플링은 P4의 가중 L1 최적화와 정확히 같지 않다. 모델 계열의 최대 성능 순위로 해석하지 않는다.
- 이미 본 역사적 분할이며 독립 최종 평가가 아니다. B1 발표 시점은 3일·837개 원본 표본과 보수적인 24시간 지연 가정에 근거하며, 전체 4년 파일별 공개 이력을 모두 감사하지 않았다. 사전학습 가중치의 공개 시점 조건 해석도 운영팀 확인 전이다. 공식 제출 적격 판정으로 표현하지 않는다.

실행기 전체 처리 기록은 B1 168.870초, B2 6637.236초, B3 900.624초다. 별도 독립 검산은 B1 41.295초, B2 92.978초, B3 51.933초였다.

B2 F3-r17은 배터리 2% 방전으로 SIGSTOP했다가 사용자 충전 확인 후 AC/87%를 확인하고 SIGCONT했다. 벽시계 전원 대기는 7771.814초로 별도 기록했다. 이 값은 Mac 절전 등을 제외할 수 있는 실행기 perf_counter와 같지 않다. B2의 원시 처리/활성 추론 시간에는 일부 대기가 포함되므로 순수 계산 속도로 비교하지 않는다. 충전 감시기의 ps 권한 오류는 기록했고 해당 B 프로세스를 직접 검증해 재개했다. 예측·모델·문맥·설정은 유지됐으며 재개한 결과도 독립 재예측 검사를 통과했다.

B1은 CPU 4스레드, B2/B3는 맥북 M1 Pro/16GiB의 MPS와 CPU 4스레드를 사용했다. B 전용 환경만 설치했다. RSS와 GPU driver 관측값을 더해 동시 전체 메모리라고 보고하지 않는다. 서로 다른 연산 경로·학습 표본·캐시·전원 대기 때문에 시간은 모델 고유 속도 순위가 아니다.

## 검증과 보관

전체 원본 라벨/용량/키·마스크, 야간 0, 25:75, 독립 NumPy W와 월·팀 합계, 과거 학습 문맥과 전처리, 예보 모델마다 1,024행 재생성·재예측을 검산했다. B1은 전체 일별 캐시 checksum과 31멤버 요약→시간별 4입력 변환도 대조했다. B3의 문맥/라벨/중앙값/선택 위치가 B2와 같은지도 확인했다. 세 실행의 verification.json은 모두 passed이며 마지막 관련 검사 28개도 통과했다. 실제 B2/B3 데이터 계산은 OS 네트워크 차단과 로컬 가중치로 수행했다.

- 상세 결과: `outputs/b1_annual/`, `outputs/b23_tabpfn/`, `outputs/b23_tabicl/`의 summary/verification/source/모델 또는 문맥/예측/월별 CSV.
- 공유 집계: [연간·월별·팀별 JSON](../experiments/b/2026-11-04-b-lane-results.json). 원본행·예측·가중치는 Git에서 제외한다.
- 출처와 고정 설계: [B1](../experiments/b/2026-11-04-b1-gefs.md), [B2/B3](../experiments/b/2026-11-04-b23-foundation.md). Built with PriorLabs-TabPFN. TabICLv2 ©2025 Soda team@Inria.
- 코드 기준은 `da77ca2` + 실행 당시 미커밋 파일이다. 각 summary의 source_sha256와 source/에 실행 소스 사본을 보존했다. 환경 lock·설치/데이터 검사·CLI 최초 실패·DNS 재수집·전원 중단 로그도 B outputs에 남겼다.

다음 기기에서는 완료한 모델을 다시 학습하지 않는다. B의 다음 성능 후보는 B1로 보존한다. A 결과와의 통합·추가 튜닝·공개 시점 규정 확인·최종 전체 학습·제출은 별도 후속 범위다. 공통 P4 실행기와 평가 계약은 고정한 상태다.


## 결과 파일을 찾는 방법

2026-11-05에 B 내부 결과물을 정리했다. 실제 결과는 `outputs/runs/b1_gefs`, `outputs/runs/b2_tabpfn`, `outputs/runs/b3_tabicl`에 있으며, 수집 캐시는 `outputs/datasets/gefs`, 내려받은 가중치는 `outputs/models/foundation`에 있다. 이전 이름은 호환 링크로 유지한다. [폴더 구조와 검사 방법](../PROJECT_STRUCTURE.md).

이동한 4,795개 파일의 해시 보존과 관련 검사 28개를 재확인했다. 원래 실험의 소스·모델·예측·설정과 집계 수치는 바꾸지 않았다. GitHub 공유 대상은 코드·설정·문서·집계뿐이며 상세 예측과 가중치는 로컬에 남는다.
